# 全自动交易系统一致性差距分析

> 从职业日内期权交易员视角，评估当前全自动交易系统离「全年 250 个交易日保持一致交易水平」这一理想状态还有哪些可改进之处。
>
> 评估日期：2026-06-15。基线：已落地 live-trading 四阶段硬化（fill 检测 / 幂等 / 锁 / sizing）与 Tier 1+2（闭环学习 / 亏损熔断 / 组合敞口 / 宏观感知）。

## 总览结论

系统已把**单笔交易的安全性**（fill 检测、幂等、锁、sizing）和**单日的纪律**（时段感知、亏损熔断、隔夜禁令）做得相当扎实，Tier 1/2 也把「闭环学习 + 组合敞口 + 宏观感知」接进了决策。

但「全年 250 天保持一致水平」考验的不是单笔或单日，而是**跨日的状态管理、归因的诚实度、以及对自身漂移的免疫力**。职业交易员和散户的真正差距就在这里。

---

## 缺口 1：没有真正的复盘闭环验证（最致命）

现状：`track_record_summary` 把胜率、信心-收益校准喂回 prompt，方向正确。但有两个硬伤：

- **归因是软的、口语化的**。`avg_confidence_vs_return` 这种单一标量塞进 prompt，LLM 会「看到但不真信」。职业复盘是**结构化分类**：这笔亏损是入场错（thesis 本身错）、择时错（方向对但早了）、风控错（止损位置不对）、还是执行错（滑点/未成交）？不同归因导向完全不同的修正。系统现在无法区分「策略有效但今天运气差」和「策略系统性失效」。
- **没有 A/B 的事实基准**。系统从不知道「如果不听 LLM、只按确定性规则交易，结果会怎样」。没有对照组，永远无法证明 AI 的 alpha 是正还是负。这是 Tier 3 backtesting 被推迟的真实代价——目前是在用真金白银做没有对照组的实验。

> 改进：把复盘从「喂一个胜率数字」升级为**结构化归因表**（entry/timing/risk/execution 四类错误计数），并跑一条 shadow 确定性策略作为对照基准。

## 缺口 2：记忆是「健忘的」——只有 6 个 cycle，且当天清零

现状：`_MEMORY_KEEP=6`，`session_date_et` 换天即 reset counters。

- **没有跨日记忆**。昨天在 SPY 上连吃三个假突破，今天开盘它不记得。职业交易员最值钱的就是「我对这个标的、这个 setup 的历史手感」。
- 6 个 cycle 在 5 分钟间隔下只覆盖 **30 分钟**。午盘发生的事，尾盘就忘了。
- 记忆是 thesis 文本 + P&L，**没有市场状态指纹**（当时的 VIX/IV regime/ORB 形态），「上次类似环境我怎么做的」这种检索做不到。

> 改进：增加一层**跨日的、按「标的 × setup × 市场状态」索引的长期记忆**，让今天的决策能检索到历史相似环境的真实结果。这是从「会话记忆」到「经验」的关键一跃。

## 缺口 3：熔断是单向、单维的，缺少「状态机」

现状：日内亏损 ≥ 阈值 → 当天转 dry-run，隔天自动恢复。好，但职业风控是**多级、多维、且有恢复路径**的：

- **只有日内一个时间尺度**。没有「连续 3 天亏损 → 降低 sizing」「周回撤 ≥ X% → 暂停该 preset」这种**跨日渐进降级**。一个会爆仓的策略，会先在日线上连亏几天才触及单日熔断。
- **恢复是无条件的**（隔天满血）。职业做法是触发熔断后**缩量复出**（half-size），用几笔小赢确认状态恢复后才放回正常仓位。现在「今天熔断、明天又全力开干」，等于没从亏损里学到 sizing 教训。
- **维度单一**：只看 realized+floating P&L 总额。没有看**胜率突变**（今天 0/5）、**滑点异常**（成交质量恶化，往往是流动性/数据问题前兆）、**连续止损次数**。

> 改进：把熔断从布尔标志升级为**风险状态机**（normal → reduced → halted → recovering），输入是多时间尺度（日/周）× 多维度（P&L/胜率/滑点/连损），恢复要经过缩量确认。

## 缺口 4：Sizing 是静态的，不随「状态」和「边际」调整

现状：`allocation_pct` 由 LLM 决定，硬上限来自 preset。但一致性高手的资金曲线之所以平滑，靠的是**动态 sizing**：

- 没有 **Kelly / 波动率目标** 这类把仓位和「当前胜率×赔率」或「当前 IV」挂钩的机制。VIX stressed 和 calm 时用同样的 `max_allocation_pct_per_trade`，意味着高波动期承担了过量风险。
- 没有**基于近期表现的杠杆调节**（连赢适度加、连亏自动减），与缺口 3 的「缩量复出」呼应。

> 改进：在 LLM 的 `allocation_pct` 之上叠一层**确定性 sizing 调制器**：`final_size = llm_size × vol_target_factor × performance_factor`，把波动率和近期状态显式纳入，避免 LLM 情绪化下注。

## 缺口 5：LLM 决策的不可复现性 = 一致性的天敌

LLM 交易系统的根本矛盾，但可缓解：

- **同样的市场，两次 cycle 可能给出不同决策**（temperature、provider failover 到不同模型）。backup provider 故障转移是好事，但不同模型的「交易人格」不同，**换 provider 等于偷偷换了交易员**，一致性无从谈起。
- 没有**决策的确定性护栏校验**：LLM 说「高把握」，但系统不会用客观指标（IV rank、流动性、价差）去**驳回**一个客观上是垃圾的机会。门禁是 schema 校验，不是「质量校验」。

> 改进：(a) 锁定/标注每个决策用的具体模型，provider 切换在归因里可见；(b) 在 LLM 决策后加一道**确定性质量闸**（流动性、价差、IV rank 不达标直接降级为 observe），让规则给 LLM 兜底，而不只是反过来。

## 缺口 6：缺少「元监控」——系统不知道自己在漂移

全年一致最隐蔽的杀手是**慢性漂移**：数据源悄悄退化、某 API 限流变频繁、市场 regime 变了而策略没跟上。

- 有 `/api/health` 浅探活，但没有**交易质量的时间序列监控**（本周实际滑点 vs 上周、fill 率、决策延迟、dry-run 占比突变）。
- 没有 **regime change 检测**：2026 年的 SPY 和 2025 年的不是一个市场，但 preset 阈值是写死常量。

> 改进：建一块**元监控面板**，跟踪滑点/fill率/胜率/各 phase 表现的周环比，任何指标偏离基线 N 个标准差就告警。这是「全年一致」从愿望变成可运维目标的前提。

## 优先级建议

| 优先级 | 改进 | 为什么 |
|---|---|---|
| **P0** | #1 结构化复盘 + shadow 基准 | 没有对照组，其他一切优化都无法验证 |
| **P0** | #3 多级风险状态机 + 缩量复出 | 直接决定回撤深度，是「活下来」的前提 |
| **P1** | #2 跨日长期记忆 | 把「会话」变成「经验」，一致性的复利来源 |
| **P1** | #4 动态 sizing 调制器 | 平滑资金曲线，和 #3 协同 |
| **P2** | #5 模型锁定 + 质量闸 | 消除「偷换交易员」的隐性方差 |
| **P2** | #6 元监控 | 防漂移，让一致性可运维 |

## 一句话总结

已经造好了一辆安全的车（不会爆胎、不会闯红灯），现在缺的是让它能在不同天气、连续 250 天跑出同样圈速的「车手状态管理系统」——**结构化复盘、跨日记忆、渐进风控、动态仓位**，这四件事是职业和业余的真正分水岭。
